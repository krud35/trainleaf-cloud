# Trainleaf mobile — localisation (English, Polski, Français, Español)

Base: source snapshot `claude-i18n-base-ui04-20261004-160924Z` (candidate 0.4.0 / versionCode 4).
Scope: the mobile client in `mobile/`. The web app is not changed. The release number is not changed.

## How it works

| Part | Where | Notes |
|---|---|---|
| Languages and locales | `mobile/src/i18n/locale.ts` | `en` → en-GB, `pl` → pl-PL, `fr` → fr-FR, `es` → es-ES |
| Preference | `mobile/src/i18n/languageStore.ts` | `localStorage['trainleaf-language']`; missing, invalid or unreadable → English. The device language is never read. Outside the profile database and the backup schema, like the theme. |
| Start-up | `mobile/index.html`, `mobile/src/i18n/boot.ts` | The existing inline appearance bootstrap also sets `<html lang>`; its CSP hash is still generated by `mobile/vite.config.ts` from the script text. `boot.ts` is imported in `main.tsx` right after the theme boot, before the first render and before the database opens. |
| Dictionaries | `mobile/src/i18n/messages/*.ts` | 35 namespaces, 1412 keys per language. English defines keys and parameters; `defineMessages` makes a missing or extra key in another language a compile error. |
| Translating | `mobile/src/i18n/index.ts` | `useI18n()` in components (`t`, `n`, `date`, `language`, `setLanguage`), `currentTranslator()` outside React. Keys are typed as `<namespace>.<key>`; parameters are typed from the English text. |
| Plurals | `mobile/src/i18n/core.ts` | A plural message is `{ one, few?, many?, other }` chosen with `Intl.PluralRules`; Polish requires all four forms. Every form is a complete sentence. |
| Dates and numbers | `mobile/src/i18n/format.ts` | Stored days stay `YYYY-MM-DD`. `parseDecimal` accepts a comma or a dot; a `5:30` pace is never parsed as a number. |
| Selector | `mobile/src/i18n/LanguageControl.tsx` | Onboarding and Settings (`SettingsView`), recovery screen (`main.tsx`). Uses the existing `theme-control` styles; no new CSS. |
| Error codes | `mobile/src/data/errors.ts` | `AppError(code, diagnosticText, params)`. The interface translates `errors.<code>`; the diagnostic text is never matched or shown. Zod issues carry the code as `error:<code>`. |
| Factory content | `mobile/src/i18n/factory/` | Exercise names, notes, cues and variants, built-in templates and period presets in four languages. |

Everything is bundled; no translation service and no network request is used. Nothing is replaced in the DOM: components re-render through `useSyncExternalStore`, so open forms keep their state.

## Rules that protect data

- User content (notes, own names of workouts, exercises, events, templates) is never translated.
- IDs, enums, backup keys, stored results and snapshots are unchanged. Changing the language writes nothing to the database.
- A factory text is translated only when **that field** of a record still equals the factory text of the **same exercise ID** (`exerciseText`). A changed field, an own exercise, an unknown ID and an older snapshot with other wording keep the stored text. The current catalog description is never substituted for a historical one.
- "Create your own copy" of a built-in exercise or template writes the copy in the current language; from then on it is ordinary user content.
- Removed factory dosing recommendations are not restored.
- CSV column names and row types, export file names and the `purpose` text inside the recovery file are part of the stored format and stay as they are.
- The load formula, weights and `trainleaf-v1` versioning are untouched; the help texts keep "not scientifically validated" in every language.

## Adding or changing a text

1. Add the key to the English block of the right namespace, then to `pl`, `fr`, `es` (TypeScript reports a missing key).
2. Use `{name}` parameters and whole sentences; for a counted noun use a plural object with `{count}`.
3. Run the checks below. A new user-facing error needs a code in `data/errors.ts` and a message in `messages/errors.ts`.

## Checks

```
npm run mobile:typecheck
node --test tests/mobile-*.test.mjs mobile/src/features/theme/theme.test.mjs
node tools/i18n-coverage.mjs        # keys, parameters, plural forms; no fallback
node tools/factory-coverage.mjs     # factory catalog in four languages
npm run mobile:build
npx playwright test --config mobile/playwright.config.ts
```

`mobile/playwright.config.ts` has two projects: `polish-regression` (the earlier specs, started with Polish saved) and `localisation` (`mobile/tests/localisation.spec.ts`, started without a saved language). `TRAINLEAF_E2E_PORT` moves the preview to another port; `PLAYWRIGHT_BASE_URL` must then point to the same port for `full-flow.spec.ts` and `offline.spec.ts`. `TRAINLEAF_SCREENS=<dir>` saves the 360 px screenshots.

## Known limits

- The label of the native file chooser button ("Choose file") comes from the browser or the Android WebView and follows the system language, not the app language.
- A notice that is already on screen keeps the language in which it appeared until it is replaced; error messages follow the language because they are stored by code.
- Technical errors without a code (for example a storage engine message) are shown as the platform reports them.
- The Polish catalog stays the canonical stored form of built-in exercises; `nameEn`, `notesEn`, `cuesEn`, `variantsEn` remain in the data model and in the own-exercise editor.
